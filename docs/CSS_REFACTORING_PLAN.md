# План рефакторинга CSS (webapp/css/style.css)

Версия: 1.0  
Основа: `docs/CSS_STYLE_AUDIT_REPORT.md`, фактическое содержимое `webapp/css/style.css` (~10 118 строк).  
Принципы: композиция, инкапсуляция, SOLID в терминах CSS (tokens/base/layout/components/pages/utilities), низкая связность между модулями, высокая — внутри.

---

## A) Executive summary

**Что делаем:** Поэтапный рефакторинг монолитного CSS (~10 118 строк) без изменения визуальной логики: устранение критичных багов (дубликат анимации, разнобой брейкпоинтов, отладочный код), введение дизайн-токенов, снижение `!important` и селекторов по `[style*="..."]`, затем модульное разбиение по слоям (tokens → base → layout → components → pages → utilities).

**Почему:** Снижение риска регрессий при доработках, единообразие брейкпоинтов и анимаций, возможность темизации и поддержки без «перебивания» правил, подготовка к возможному разбиению на файлы/сборку.

**Риски:** Рефакторинг без смены сборки — только правки внутри одного файла и/или добавление новых файлов с импортами; риск регрессии при массовой замене цветов/отступов и при замене `[style*="..."]` (требуется синхронные правки в JS).

**Quick wins (1–2 часа):**
1. **Дубликат `@keyframes modalSlideIn`** — переименовать в `modalSlideInFromBottom` (стр. 2197) и `modalSlideInFade` (стр. 5507), обновить `animation-name` в стр. 2179 и 5612.
2. **767px → 768px** — заменить в трёх медиа-запросах (стр. 7882, 7990, 8316).
3. **#edit-product-page DEBUG** — выставить `--ep-debug: 0`, скрыть `::before` (`display: none`), убрать `background` у `::after` в двух местах (стр. 10078, 10092); логику отступа снизу не трогать.

## B) Архитектурная модель (ООП для CSS)

### Слои и ответственность

| Слой | Назначение | Содержимое (примеры) | Кто может импортировать |
|------|------------|----------------------|--------------------------|
| **Tokens** | Единственный источник правды для цветов, отступов, высот, радиусов, теней, z-index, брейкпоинтов (комментарий или custom properties). | `:root` с переменными: `--color-*`, `--space-*`, `--radius-*`, `--z-*`, `--breakpoint-*`. | Все нижележащие слои. |
| **Base** | Сброс и глобальные элементы: типографика, html/body, кнопки по умолчанию, скроллбар. | `html`, `body`, `button`, глобальные переменные Telegram (фиксация цветов). | Layout, Components, Pages, Utilities. |
| **Layout** | Структура страницы: фиксированный header, контейнеры страниц, области контента, safe-area. | `header`, `.operation-page`, `.operation-page-content`, `.form-page-content`, общие паттерны top-menu. | Components, Pages. |
| **Components** | Переиспользуемые блоки без привязки к странице: кнопки, карточки, модалки, инпуты, бейджи, bottom sheet. | `.glass-btn`, `.modal-content`, `.edit-product-field`, `.cart-item`, dropdown, toggle. | Pages, другие Components. |
| **Pages** | Стили, привязанные к конкретной странице/экрану (по id или контейнеру-странице). | `#product-page`, `#cart-page-new`, `#edit-product-page`, `#admin-page`, `#profile-details-page`, страница операций. | Никто (верхний уровень). |
| **Utilities** | Вспомогательные классы: скрытие, видимость, отступы-утилиты (если появятся). | `.is-hidden`, `.is-visible`, scrollbar-hide (если вынесено). | Любой слой при необходимости. |

**Правила зависимостей:** Токены не зависят ни от чего. Base — только от Tokens. Layout — от Tokens и Base. Components — от Tokens, Base, при необходимости Layout. Pages — от всех предыдущих. Utilities — от Base (или без зависимостей). Запрещено: Pages не должны импортировать другие Pages; Components не должны знать id страниц (страница задаёт контекст через обёртку).

### Naming и специфичность

- **Конвенция:** BEM-подобная: блок__элемент--модификатор. Префиксы по типу блока: страницы — по id (`#edit-product-page`) или классу страницы (`.product-page`); компоненты — по имени (`.edit-product-form`, `.operation-top-menu`). Модификаторы состояния — суффикс или класс `.is-*` (`.is-visible`, `.is-saving`).
- **Специфичность:** Максимум два уровня для компонентов (например `.block .block__element`). Страничные переопределения допускают id или класс страницы + один уровень (например `#edit-product-page .edit-product-form`). Избегать длинных цепочек и лишнего `!important`; где нужен приоритет — повышать за счёт порядка и одного id/класса страницы.

## E) Обязательные точечные фиксы из отчёта

### E.1 Дубликат @keyframes modalSlideIn

- **Новые имена:**  
  - Первая анимация (стр. 2197): **`modalSlideInFromBottom`** — выезд снизу (translateY(100%) → 0).  
  - Вторая анимация (стр. 5507): **`modalSlideInFade`** — появление с лёгким смещением и scale (20px, scale 0.95 → 0, 1).
- **Где менять animation-name:**  
  - Стр. **2179**: блок с `.modal-content` (или родитель модального окна) — заменить на `modalSlideInFromBottom`.  
  - Стр. **5612**: блок модалки админки — заменить на `modalSlideInFade`.
- **Регрессионная проверка:**  
  - Открыть модальное окно с контентом товара/покупки → анимация «снизу вверх» (как сейчас должно быть при первом определении).  
  - Открыть модальное окно в админке → анимация «лёгкое появление» (scale + смещение). После фикса обе анимации должны работать корректно, т.к. вторая перестанет перезаписывать первую.

### E.2 Брейкпоинт 767 vs 768

- **Стандарт:** Единый брейкпоинт для «мобилки» — **768px** (max-width: 768px для mobile-first или min-width: 768px для desktop).
- **Места замены:**  
  - Стр. **7882:** `@media (max-width: 767px)` → `@media (max-width: 768px)`.  
  - Стр. **7990:** то же.  
  - Стр. **8316:** то же.

### E.3 #edit-product-page DEBUG

- **Выключить/удалить:**  
  1. Стр. **10041:** `--ep-debug: 1` → `--ep-debug: 0`.  
  2. Стр. **10055–10066** (блок `::before`): добавить `display: none;` (или заменить существующий `display: block` на `display: none`), чтобы скрыть текст «EDIT-PRODUCT CSS OVERRIDE ACTIVE».  
  3. Стр. **10078** и **10092:** у обоих блоков `::after` удалить строку `background: rgba(0, 128, 255, 0.15);` (или заменить на `background: transparent;`).
- **Сохранить без изменений:** Всю логику отступа снизу: `--edit-product-bottom-gap`, `padding-bottom: calc(var(--edit-product-bottom-gap) + 88px + var(--tg-safe-area-inset-bottom, 0px)) !important`, `height` у `::after`, правила для `.edit-product-form`, `.edit-product-actions`, `min-height: auto`. Комментарии про «после проверки» можно сократить до одной строки: «Debug отключён; при необходимости включить --ep-debug: 1 и display: block у ::before».

## F) Метрики и цели «после»

| Метрика | Было | Цель после рефакторинга | Обоснование |
|---------|------|--------------------------|-------------|
| **!important** | 337 | ≤ 180 (первая итерация); дальше ≤ 120 | Часть оправдана (Telegram, safe-area, фиксированные панели). Цель — убрать «исторические» и часть страничных перебиваний за счёт порядка и специфичности. |
| **Хардкод цветов** (например #E35E45, #00A82E, повторяющиеся rgba акцента) | 157+ | 0 для цен и акцента; ≤ 40 для остальных (фоны/границы в rgba по мере введения токенов) | Все семантические цвета (цены, акцент, базовый фон) — через токены. |
| **Селекторы [style*="..."]** | 69 | 0 для display (замена на классы); допускается оставить единицы для других атрибутов при необходимости | Полная замена показа/скрытия на классы. |

| **Брейкпоинт 767px** | 3 | 0 | Унификация на 768px. |
